# AGENTS.md — after-build-quiz

Read SPEC.md first. SPEC.md is the source of truth; change it (with approval) before changing behaviour.

Built against Claude Code 2.1.296. The function-hooks API is early access: re-run validate + tests (and
calibration) after every Claude Code update, before any other work.

## Workflow
- Propose before coding. No files written until the proposal is approved.
- Nothing is committed until the user types exactly `confirmed working: commit N`. Commit only that step.
- No agent-attribution trailers (no Co-Authored-By, no "Generated with").
- Stage by explicit path only. Never `git add -A`, `git add .`, or `git commit -a`.
- Before any push: run the pre-push scan and report results; push is a separate step after the user says so.
  Pre-push scan: secrets/tokens, absolute personal paths (`C:\Users\`, `C:/Users/`), email addresses, any
  `*.jsonl` / `queue.json` / `active.json` / calibration results, `after-build-quiz-proposal.md`, and
  anything under `.claude-plugin/types/`.

## Hard rules (the repo is public)
- Quiz data (queue, active quiz, logs incl. answer text, calibration results) lives only in the user-level
  dataDir. Never in this repo. Test and calibration fixtures are synthetic.
- The plugin never mutates a project repo. All git goes through `hooks/git.ts`, whose allow-list is
  rev-parse, log, show, cat-file, config --get. Do not widen it.
- The plugin never gates: no hook denies, drops, rewrites or delays a tool call or prompt. Observing hooks
  pass the event on first and carry a `.catch` that passes it through.
- Quiz content reaches the user only through system notices. Never put questions, key points, gaps or
  answers in a command's `text` or `context`, or in a user-role row.
- Grading prompts must not be softened to raise scores. Any change to the grader prompt, rubric or model
  requires a calibration run, with results reported before commit.
- `after-build-quiz-proposal.md` is a private working doc: gitignored, never committed.

## Dev loop
- `claude plugin validate .` after every change; `tsc -p .`; `claude plugin test .`
- Integration: `node tests/integration/git-cat-file.mjs` (real throwaway repo in the OS temp folder; Node 24
  runs hooks/*.ts directly). `claude plugin test` has no processes, so real-git checks live here.
- Calibration: `claude -p "/quiz calibrate" --plugin-dir .` with `devMode` on (costs real model calls;
  run when the grader changes and after Claude Code updates).
- Manual runs: `claude --plugin-dir "<this folder>"` from a scratch repo in a temp dir, with `dataDir`
  set to a scratch data folder. Never test against a real repo or the real dataDir.
- `.claude-plugin/types/` is generated by Claude Code on load — gitignored, never edited.
